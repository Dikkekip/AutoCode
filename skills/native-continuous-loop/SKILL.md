# Native continuous loop

Resolve the framework root from its configured `plugins.load.paths` entry ending in `plugins/autocode`; the agent workspace may be elsewhere. Run `<framework-root>/scripts/native-continuous-loop.mjs --openclaw <cli> --board <board> --state <private-json>` to preview a tick; add `--apply` within authorized execution scope. The systemd examples serialize ticks and retry failed ticks after one minute. Use one scheduling owner per board; disable overlapping discovery/dispatch/reconcile schedules during cutover.

Each tick preserves operator pauses, waits for native operations, checks Doctor and the skill binding, then reconciles existing work. Reconciliation owns dispatch, verification, review and bounded repair. Idle capacity permits discovery every thirty minutes by default. For an authorized high-throughput profile, use `--discovery-interval-seconds 300` (validated range 60–86400 seconds). When resources permit and discovery is due, queued operator requests get a discovery attempt before reconciliation can enter long verification. For sustained operation, add `--coordinate`: one process retains its accepted long reconciliation RPC and pulses native dispatch/discovery every minute while verification runs. Only recognized workflow/verification leases permit these lightweight pulses; discovery, admission, reconciliation, release and unknown leases defer them. Existing active work prevents a replacement long reconciliation. A failed or uncertain pulse stops further pulses while the accepted owner settles. The native owner still enforces daily budgets, active-round and downstream backpressure, scope, and review gates. This changes scheduling, not model quota limits or reset credits. It records discovery admission before calling the broker so a lost response does not immediately duplicate a round.

For a stall, inspect Gateway readiness, `autocode.status`, `autocode.doctor`, and the exact Workboard card/run/session. Missing handlers, unsupported runtime contracts, unavailable workspaces, host pressure and verification failures need distinct fixes. Preserve prior attempts and recovery artifacts. Never bypass a capability, independent review, CI or deployment gate to get a green status.

Use the CLI belonging to the service runtime or the configured AutoCode command. A different global CLI can reject configuration supported by the running Gateway. If dispatch reports that a workspace is outside the caller's allowed workspaces, inspect the registered project and current Workboard `worktreeSources` delegation as well as the card's persisted grant. Doctor passing does not prove that project delegation exists. When the matching runtime supports it, authorize only the required board, registered project and source branches; preserve isolated worktree confinement rather than widening writable roots.

For each coding attempt, reproduce the observed failure, state a causal hypothesis, make a scoped correction and run the focused check. After a repeated failure, use the preserved repair history to choose a materially different approach; an unchanged retry is not progress. Exhausted recovery should block only that workflow so disjoint admitted work can continue.

Success requires fresh card/run/session/tool activity, then commit-bound verification and independent review. A timer, Gateway readiness, candidate or done card alone is insufficient. A timed-out mutation has unknown acceptance: inspect native state before retrying. The loop never resumes an operator pause or kills an active worker.
