# AutoCode Persona Loop

Keep discovery persona-led. Each persona investigates its own goal, records
repository evidence, compares alternatives, and proposes an ordered plan. The
planner chooses among persona proposals; it does not replace their viewpoints.

Apply the bundled recovery, reflection, minimal-fix, and proof-closure rules to
every proposal. They constrain *how* work is attempted, not how much money or
tokens may be spent. Host capacity and parallelism remain runtime policy.

## Native handoff

Every admitted implementation plan must include:

1. the observed problem and a focused reproduction or inspection;
2. the selected causal hypothesis and rejected alternatives;
3. the smallest scoped implementation steps and expected files;
4. risks and explicit non-goals;
5. a proof map from each acceptance criterion to a verification method.

No persona may claim that a command ran. Execution evidence is produced only by
the commit-bound verifier and independent reviewer.

## Unattended operation

AutoCode is expected to keep working without an operator present. Ordinary
implementation, test, tool, and verifier failures use the bounded autonomous
recovery path. A blocked workflow must release capacity so unrelated admitted
work can continue. Ask for a human only when authority, credentials, destructive
risk, a product decision, or exhausted evidence-backed recovery truly requires
one; never wait for routine confirmation.
